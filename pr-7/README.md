# Агент класифікації споживачів енергії

> Варіант 4 — Аналіз поведінки споживачів і автоматична класифікація (домогосподарства / бізнес). Методи: K-means, Random Forest.

## Як працює LLM і що таке агент

**LLM (Large Language Model)** — це нейронна мережа, навчена на величезних масивах тексту. Вона не "знає" фактів у звичайному розумінні — вона навчилась передбачати, який токен (слово або його частина) найімовірніше йде наступним у контексті. Саме завдяки цьому модель може підтримувати діалог, писати код, формулювати висновки.

Важливо розуміти: **LLM сама по собі нічого не робить із зовнішніми даними** — вона тільки генерує текст. Щоб вона могла, наприклад, читати файли або запускати алгоритми ML, потрібна обгортка у вигляді агента.

### Що таке агент

**Агент** — це програма, яка дає LLM можливість діяти: виконувати інструменти, отримувати результати і продовжувати міркування на їх основі. Цикл роботи агента виглядає так:

```
Запит користувача
       ↓
  LLM міркує
       ↓
  Обирає інструмент (tool)
       ↓
  Виконує інструмент
       ↓
  Отримує результат
       ↓
  LLM знову міркує → або ще один інструмент, або фінальна відповідь
```

Цей цикл може повторюватись кілька разів. Наприклад, у цьому проєкті агент спочатку аналізує датасет, потім вирішує — є мітки чи немає — і відповідно запускає або Random Forest, або K-means.

## Клієнт і сервер

Тут є два рівні взаємодії: **наш код** (клієнт) і **API Gemini** (сервер). 

Ключовий момент: **інструменти виконуються локально на вашій машині**, а не на сервері Google. Сервер лише вирішує, який інструмент викликати і з якими аргументами, повертаючи структурований `tool_call`. LangChain бере на себе роль керівника — він надсилає запити, перехоплює tool calls, виконує функції і повертає результати назад у модель.

## LangChain і інструменти (tools)

**LangChain** — це бібліотека, яка стандартизує роботу з LLM. Замість того щоб вручну формувати HTTP-запити до API і розбирати відповіді, LangChain надає готові абстракції.

Основні компоненти, що використовуються тут:

### `@tool` — декоратор інструмента

```python
@tool
def run_kmeans(path_to_csv_file: str, n_clusters: int = 3):
    """Запускає кластеризацію KMeans..."""
    ...
```

Декоратор `@tool` робить три речі:
- перетворює звичайну функцію на об'єкт-інструмент, зрозумілий LangChain
- витягує **docstring** як опис інструмента — саме його модель читає, щоб зрозуміти, коли і як викликати функцію
- витягує **типи аргументів** і передає їх моделі як JSON-схему

Тому docstring у `@tool` — це не просто документація для розробника, а **інструкція для LLM**.

### `create_agent`

```python
agent = create_agent(
    model=google_llm,
    tools=[analyze_dataset, run_kmeans, run_random_forest],
    system_prompt=system_prompt
)
```

`create_agent` збирає агента: прив'язує модель до списку інструментів і задає системний промпт — інструкцію, яка визначає, як агент має поводитись і в якому порядку використовувати інструменти.

### Системний промпт

Системний промпт — це не просто "налаштування тону". Він задає **логіку прийняття рішень**:

- Завжди починай з `analyze_dataset`
- Якщо є нечислова цільова колонка → `run_random_forest`
- Якщо міток немає → `run_kmeans`
- Після результатів ML — поясни поведінку споживачів і зроби класифікацію

## Машинне навчання

### K-means (кластеризація)

Використовується, коли в датасеті **немає готових міток**. Алгоритм сам розбиває споживачів на групи за схожістю поведінки.

- Вхід: числові ознаки (споживання, час, температура тощо)
- Перед запуском дані нормалізуються через `StandardScaler` — щоб ознаки з різними масштабами не домінували
- Вихід: номер кластера для кожного запису

Кількість кластерів `n_clusters` задається заздалегідь (за замовчуванням 3). В ідеальному випадку агент міг би підібрати її автоматично через метод "ліктя", але в поточній реалізації це фіксований параметр.

### Random Forest (класифікація)

Використовується, коли в датасеті є **цільова колонка** з мітками класів (наприклад, `household` / `business`).

- Random Forest будує багато дерев рішень на випадкових підвибірках даних
- Фінальне рішення приймається голосуванням між деревами
- Вихід: точність (accuracy) на тестовій вибірці + важливість кожної ознаки (`feature_importance`)

Важливість ознак особливо корисна для інтерпретації: агент може сказати, що, наприклад, "споживання у нічний час" — найсильніший предиктор для домогосподарств.
